## Row counts and class balance

| | count |
|---|---|
| Total rows | 30,008 |
| Fraud (`is_fraud=True`) | 1,146 |
| Non-fraud | 28,862 |
| Fraud prevalence | 3.819% |

This is a real, severe class imbalance (roughly 1 fraud row per 25 normal
rows) — not an artifact of a tiny hand-picked sample the way the old N=8
version was. `scale_pos_weight` in [`train_xgboost.py`](train_xgboost.py)
and training Isolation Forest on non-fraud rows only (see
[`train_isolation_forest.py`](train_isolation_forest.py)) are both direct
responses to this real ratio, not a precaution for a ratio that might
exist at scale.

## Correlation with `is_fraud`

See [`eda_output/correlation_heatmap.png`](eda_output/correlation_heatmap.png)
for the full feature-by-feature matrix.

| Feature | Correlation with `is_fraud` |
|---|---|
| velocity_1h | 0.522 |
| terminal_reversal_count | 0.316 |
| geo_jump_km | 0.230 |
| amount_ngn | 0.225 |
| bin_spend_rate | 0.182 |
| amount_vs_bin_avg_ratio | 0.111 |

**Correlation is descriptive, not the same thing as predictive
importance.** This column shows each feature's linear association with the
label in isolation. It is not a ranking of what XGBoost actually learned
to rely on — a feature can correlate weakly on its own but matter a great
deal in combination with others (or vice versa), and XGBoost's actual
per-feature importance is a property of the fitted model, logged
separately to MLflow by `train_xgboost.py` as `importance_<feature>`
metrics (see the model-results table in
[`models/README.md`](README.md#model-results) for the current run's real
values) — read that table for "what the model uses," and this section for
"what's associated with fraud on its own."

Two more honesty notes already documented in the training scripts'
docstrings, restated here because they belong in the EDA record too:
`amount_ngn`/`amount_vs_bin_avg_ratio` meaningfully helped the supervised
XGBoost model but measurably *hurt* Isolation Forest's anomaly-score
correlation with `is_fraud` (see
[`train_isolation_forest.py`](train_isolation_forest.py)'s docstring) —
extra dimensions are not free for an unsupervised, distance-based method
the way they are for a supervised one. And every correlation here is
circular to a degree worth naming plainly: the fraud scenarios that
produced these labels were themselves designed around velocity, geography,
and amount signatures (see
[`producer/fraud_scenarios.py`](../producer/fraud_scenarios.py)), so a
feature correlating with the label it was partly designed to predict is
expected, not an independent discovery about real-world fraud.

## Class imbalance strategy

At the real 3.819% fraud prevalence confirmed above:

- `train_xgboost.py` uses **`scale_pos_weight`** (ratio of negative to
  positive class count, computed fresh from the actual training split
  each run via `compute_scale_pos_weight()`) rather than oversampling or
  SMOTE, combined with a validation-selected decision threshold (see
  `select_threshold()`) rather than the default 0.5 cutoff.
- `train_isolation_forest.py` fits only on non-fraud rows by design (the
  model's own unsupervised assumption), with `contamination=0.02` set
  below the real 3.8% rate deliberately — see that script's docstring.
- A CTGAN-based synthetic augmentation path exists
  ([`synthetic_augmentation.py`](synthetic_augmentation.py) /
  [`validate_synthetic_features.py`](validate_synthetic_features.py)) and
  was evaluated empirically rather than assumed to help: enabling it
  measurably *reduced* XGBoost's held-out F1 (0.78 → 0.73) on identical
  real-only test data, so it is left off by default. See
  `train_xgboost.py`'s docstring for the full before/after comparison.
